## Problem statement + evidence

The module's recurring failure shape is **defined-but-unenforced**. Four live instances in `vlt-core`:

- **Lint cadence has no forcing function.** `skills/vlt-lint/SKILL.md`'s own description says "proactively after several ingestions," but nothing counts ingests. Last scoped lint: 2026-06-27 17:38 (Librarian/Gwyn). The tell: three same-week artifacts cite three different backlog figures — "~13 ingests" (pressure-test), "14 ops / 9 ingest" (synthesis), 11 by a fresh header grep for this filing — because no authoritative reader exists. The disagreement *is* the problem statement.
- **The extraction firewall sat "checkable but unchecked" for 4 days** (2026-06-09 amendment → 2026-06-13 `vlt-lint` Step 2b) — enforced within hours of being *wired*, invisible until then.
- **Dispatch failure modes #3/#4 deferred "until it bites"** with no numeric definition of biting — the same shape, freshly minted a week before the run.
- **Staleness markers specified, zero pages carry one** (World Cup / NFL draft / policy-deadline pages past their events).

Everything that already works in this vault — the dirty-tree SessionStart hook, the log+commit pairing, the dispatch drain — has the same anatomy: machine-readable state + an attached moment + a visible surface. Everything that fails is missing at least one of the three.

Rider evidence: the open dispatch board holds a pointer routed 2026-06-13 from a 2026-05-23 capture ("should good writing be invisible?") — six weeks from capture, still open — and the backlog's philosophical items (lone-page index categories, finance contradictions) are equally old. Nothing distinguishes *waiting-on-user-decision* from *waiting-on-partner-bandwidth* from *waiting-on-the-world*, so `vlt-dispatch ledger` shows age but cannot triage.

## The decision and its rationale

Four pieces, one structural correction over the brainstorm's original proposal:

1. **Vitals = a derived view, never a stored file.** A small read-only script computes `ingests_since_lint` + `days_since_lint` from `{log}` header grammar, `open_pointers` + max open-pointer age from `{dispatch}` unchecked rows, and (once the `review_after:` key lands — see `2026-07-06-091006-review-after-freshness-key.md`) `expired_pages` from frontmatter. Non-zero exit on any failure.
2. **Tripwires = `_agent/tripwires.yaml`**, each wire `id, metric, threshold, owner, moment, surface_text` (+ `review_after`, aligning with the deferral schema in `2026-07-06-091004-no-boundary-without-a-bell.md`). Seeded with two real wires: `lint-debt` (`ingests_since_lint ≥ 10`) and `relay-overdue` (open pointer > 21 days). New rule at deferral/mint moments: **no deferral without a wire.**
3. **Moment = a second SessionStart hook** rendering a ≤1-line health strip (tripped wires only; silent when green; "vitals unavailable" on reader failure — never an empty healthy-looking strip).
4. **Surface = `vlt-dispatch ledger` computes a "Tripped wires" section live** from registry + vitals — the existing drain discipline pays what it shows.

**The rejected alternative (record this as a design invariant): stored counters.** "Every vault-writing op increments `vitals.json` as a mandatory final step" was the original proposal and the pressure-test killed it as a recursion trap: the increment obligation is *itself a prose-enforced obligation executed by an LLM* — the exact defined-but-unenforced shape, now load-bearing for the enforcement layer, and a skipped increment yields a **false-healthy** reading (worse than none). It is also a universal merge-conflict point: every parallel session would write one shared file, breaking the disjoint-file-set property path-scoped commits depend on. Derive-don't-store dissolves both at once, plus the adoption cost (no op is modified to get value). The counters the kit wants already exist as facts in records whose writing is *already enforced* (log+commit pairing, dispatch append/check-off); the missing piece was only the reader. **Invariant for all enforcement work: no mutable stored counters — derived or append-only state only.** Plan B for a genuinely underivable counter is an append-only events file folded at read time, never a mutable store.

Also rejected/deferred, each behind an explicit adjustment trigger rather than shipped: stored auto-created ledger rows (needs a writer moment; surface-as-view first, promote per-wire after two consecutive unactioned trips), scheduled headless runs (armed only if a tripped wire is >7 days old at first render), the no-go gate and debt-aware ingest (escalation tiers). Attention budget is a hard constraint: **one strip line**; everything else is pull.

## Upgrade/migration path for existing installs

Everything is additive; no existing record is rewritten. Under `vlt-upgrade` merge-not-replace:

- **Scripts** ride the force-reinstall class (Step 2 merge-copy, like `assets/workflows/*.js`) — module-owned code refreshes cleanly.
- **`_agent/tripwires.yaml`** is vault-grown state: if the vault already carries a registry (vlt-core will, after slices 0–3), merge wires **by `id`** — local thresholds win, ship-seeded wires are added only if absent, local wires are never dropped. Record the merge in `{upgrade_ledger}`.
- **`settings.json` hook registration** is idempotent by command path — re-running setup/upgrade never duplicates the hook and never touches unrelated vault-local hooks.
- **Contract grammar section** lands as a section append; the existing `.baseline/` stash + `base_divergence` detection surfaces any vault whose hand-edited contract conflicts.
- **vlt-core specifically:** once slice 0 lands, the prototype will live at `_agent/vitals.sh`; the shipped `.claude/hooks/vitals.sh` supersedes it — the upgrade removes the local copy and notes it in the ledger. A local tripwires.yaml, once seeded by slices 0–3, is kept as-is (it becomes the reference implementation).
- **`blocked_on`** is optional; absence means untagged, so every existing backlog entry and dispatch row stays valid with zero backfill.

## Latent bugs surfaced

1. **Two "since last lint" definitions can disagree.** `vlt-lint` Step 0 scopes by filesystem mtime (`find -newermt <last-lint-ts>`) while the lint-debt metric counts log `ingest` headers after the last `lint` header. A file touched outside an op (or an op editing an old page) diverges the sets: the strip can say "10 ingests," the scoped lint covers a different file set, and the counter still resets. The module should pin one definition per consumer — the wire measures op-debt; Step 0 measures file-scope — and say so in both places (change 6).
2. **The grammar holds, but not strictly.** Probe run for this filing: 184 headers in `_agent/log.md`, 175 (95.1%) match the strict grammar; the 9 misses are 7 partner-less headers — including two partner-run ingests that simply dropped the `(partner)` — and 2 capitalized `(Researcher)`. A strict parser silently undercounts; a case-insensitive, paren-tolerant parser reads 100%. Change 4 contracts the forward grammar and mandates the tolerant parser for history.
3. **The kit's moment is currently unprovisionable module-side.** The SessionStart hook mechanism exists in vlt-core only as a hand-wired local file; vlt-setup has no hook-install or settings.json capability at all (change 3 closes this — flagged because any *other* future hook-shaped feature hits the same wall).

## Open design questions to decide module-wide

1. **Where does module-owned executable code live in an installed vault?** Proposed: `{root}/.claude/hooks/` beside the workflows precedent. `_agent/` is rejected here — it is vault-grown state, and mixing force-refreshed code into it muddies merge-not-replace. The attestation (`2026-07-06-091005`) and packaging-lint (`2026-07-06-091002`) filings may also ship scripts; decide once.
2. **One metric vocabulary or two?** Proposal: tripwires.yaml `metric` ids are canonical; the bell filing's enforcement-block `counter:` field must reference an existing metric id rather than coin its own.
3. **Is `days_since_lint` a third seed wire or display-only?** The pressure-test seeds only two wires (alert-fatigue budget); recommend display-only until a time-based lint failure is actually observed.
4. **`blocked_on` shape:** inline greppable facet on pointer/backlog lines (proposed) vs frontmatter; and should `external-event` require a companion date — which dovetails with the `review_after:` key (`2026-07-06-091006`)?
