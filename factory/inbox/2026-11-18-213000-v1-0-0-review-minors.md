# v1.0.0 shipped with nineteen minor review findings unaddressed

_Filed 2026-11-18 from the factory, the day v1.0.0 was released. Source: the independent whole-branch review of `vlt-1.0` run before the release. Its one Critical and four Important findings were fixed before the tag (commit `d50a9e0`). The Minor findings below were deferred by the owner's standing rule for that build and are recorded here so they are not lost. Kind: `defect` for the engine and check items, `pattern` for the text items. Evidence is the reviewer's, at the `file:line` it cited against the release tree; none has been re-grounded since._

Each item is small and independent. Ground it against current source before changing anything: line numbers are from the review, not re-checked.

## The seed-and-pull engine (`scripts/kits.py`)

1. **`diff` crashes on a non-UTF8 vault file** (`UnicodeDecodeError`). Setup's step 4 would hit it on a `kept-yours` binary.
2. **A `./`-prefixed, absolute or `..` path is refused as "no kit ships this path".** Safe, but the message misleads. Normalise the path, or say "give the vault-relative path".
3. **The lock write is not atomic, and `status` rewrites the lock as a side effect.** A crash mid-write leaves an unreadable lock.
4. **A retired file already absent from the vault reports `unchanged` forever**, leaving a stale lock row. This was a recorded ruling at build time (the state table tests "vault matches kit" first); the cost is the stale row.
5. **`seed` with an empty kits directory writes an empty lock and exits 0** without a word.
6. **Untested paths:** `leave` on a retired path, `seed`'s `vault-removed` line, `stamp_versions`, and `diff` on an absent file.

## The checks

7. **The tool-README check counts every directory directly under `_agent/tools/`**, so a hidden directory, a `__pycache__` or a `.pytest_cache` there fails it (`_agent/tools/checks/run.py`).
8. **`companion:` paths are not checked** by `index.py --check`. A path that does not exist passes; only a repo test covers the shipped ones.
9. **A pipe character in `need:` breaks the index table row.**
10. **The wiki check treats `a.md` and `sub/a.md` as one page**: one index row satisfies both (`_agent/tools/wiki/check.py`).
11. **No timeout** on a hanging check, in `check.py` or `run.py`.

## Rules that disagree with each other

12. **`dropped`.** `set-up-a-zone.md` has a session mark a task moved off the vault board as `dropped`. `task-board.md` says `dropped` is set only on the owner's word and means "decided against".
13. **"Nothing is deleted."** `_meta/vault.md` says so without exception. `research.md` removes its WIP file and `feedback.md` deletes the pasted outbox file.

## Gaps in the shipped text

14. **`_agent/feedback-outbox/` is not in `_meta/vault.md`'s "Where things live".**
15. **The vault board has no README.** `task-board.md` takes `sub:` and `theme:` values from a zone README, and `_agent/tasks/` has none; its `VLT` prefix is stated only in prose.
16. **The playbooks README speaks of a playbook "that belongs to the zone".** Playbooks have a `domain:`, not a zone.
17. **`feedback-field-contract.md` sends a vault reader to `factory/inbox/README.md`**, a file in this repo, whose older sections name removed skills.
18. **Stale comments in two issue templates:** `.github/ISSUE_TEMPLATE/field-supersession.yml` and `config.yml` still mention a Cycle 11 item and BMAD-METHOD.
19. **The research-note schema ships in the core kit's `_meta/frontmatter.md`.** The design's kit table puts it in the `research` kit. The build plan chose core so all schemas share one file; the design and the tree disagree.

## What was also left unexercised at release

Not review findings, recorded for the same reason: the Templater task template (`_agent/templates/zone-task.md`, the **New** button on a board) has not been run in Obsidian. The plugin install, `vlt-setup` and the `.base` files were confirmed in the field vault on 2026-11-18.
