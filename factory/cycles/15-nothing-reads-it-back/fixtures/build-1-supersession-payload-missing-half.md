### what_happened

**This is a `supersession` filing — it asks for a retirement, not a fix.** The rule below is not
misbehaving by accident; it has stopped earning its place, because a net now enforces what it was
standing in for. Filed under the class `factory/inbox/README.md` defines for exactly this, and it
carries both required halves.

**Half 1 — the rule now redundant.** `extraction.md` (`version: 9`) states that a module-canonical
but non-PARA `type:` (`wiki`, `research`, `session`, `note`, `idea`) sitting in a PARA folder is a
mis-typed or mis-placed artifact — retype it, or relocate it, **"never to declare module vocabulary
as vault-grown overlay schema."** It carries one exception, stated as a singular at four sites:
*"one carve-out **by name**: the `{wiki}` subtree under `{resources}`."*

**What it was standing in for: the folder asserting a property the file already declares.** Here the
property is *what the artifact is*. When the contract was authored, that proxy was necessary — the
honest frontmatter fields carried no enforcement, so location was the only protection available.

**Why it is redundant now, and not merely inconvenient.** A file at a PARA address already declares
who wrote it (`author:`), how far to trust it (`trust:`), and that its writer ran its verification
pass (`verified_by:`/`verified_at:`) — each checked across the whole PARA population by a shipped
net. **`type:` is the one field of that quartet whose declaration its folder still overrules.** Three
of the four are believed when honest; the fourth is believed only if the folder approves the noun.

**And the rule inverts against accuracy.** The overlay route stays open for *vault-grown* vocabulary
and is closed **only** to the module's own words. A vault typing agent-written periodicals
`dispatch-brief` is conformant today; a vault that typed the same artifacts `research` — the
module's own accurate word for a dated, single-pass, `trust: raw` snapshot — is permanently not.
**A recognized-vocabulary rule that punishes correct vocabulary has stopped serving its stated
purpose.**

**The ask, precisely.** Retire the **prohibition** — *"never to declare module vocabulary as
vault-grown overlay schema"* — and let a vault declare a typed subtree.

⚠ **`para_type_unknown` is NOT retired and this filing does not ask for that.** A genuinely
undeclared value (`type: banana` at an `{areas}` address) must still land loud. The net keeps its
job; it stops being fed a rule that answers a question the file already answered honestly.
**Retiring a prohibition is not retiring its enforcement** — that distinction is the whole ask.

⚠ **And the `{wiki}` carve-out retires with it, in the same act — this half is not optional.**
Retiring the prohibition while leaving `{wiki}` a named exception converts a category back into an
allowlist. A build that ships half of this has shipped another perimeter patch.

### evidence

**Half 2 — the mechanism that supersedes it.** Two, both already shipped, populations stated rather
than assumed:

1. **The `para_*` honesty nets — same population, both modes.** `para_type_unknown`,
   `para_author_unknown`, `para_status_unknown` and `para_writer_unauthorized` run over files under
   `{projects}`, `{areas}` and `{resources}` in **both** lint modes. They were extended across the
   entire PARA population in an earlier release, and shipped *beside* the prohibition rather than
   *in place of* it. Population coverage is exact: the nets judge the identical file set the enum
   governs.
2. **Declare-at-birth — the same rule's own escape, already trusted.** The statement already admits
   *"any vault-declared schema in `{overlays}/extraction.overlay.md`"* into the closed set. The
   mechanism for a vault to say *"this value is legal here, and I am on record saying so"* exists,
   ships, and is relied upon. The prohibition does not doubt that mechanism — it carves one class of
   value out of a route it otherwise accepts.

**Measured in the origin vault, not asserted:**

- **146** `type: wiki` files under the carved-out subtree are legal.
- **9** identically-shaped files under a sibling `{resources}` container are a permanent finding —
  same honest frontmatter, same declared type discipline, different folder name. The population grew
  **5 → 8 → 9 in three days**; the ask is about the `type:`, not the count, but the blast radius
  compounds.
- The two legal responses the rule offers are **both unavailable without writing something false**:
  retyping asserts a `type:` the vault holds to be wrong, and relocating asserts a placement it
  holds to be wrong.

**A completeness-claiming list of one.** *"One carve-out by name"* is an enumeration that has already
fallen behind the real population — the documented drift failure, inside the rule meant to prevent
mis-declaration.
