# Build #2 — `resources/` gains PARA parity

A write to `resources/<not-wiki>/` falls between the operating contract's hard rule's grant
and its prohibition — Layer 3 is defined as `{projects}`/`{areas}` only (`:66`), the hard
rule prohibits "nothing else **in PARA**" (`:68`), and the `resources/` structure-table row
(`:41`) states no write posture at all — so a careful partner cannot answer a legality
question from the bundle (A11-10). The owner ruled a **fifth shape** none of the filing's
four proposed: `resources/` is **granted the same posture as `{areas}` and `{projects}`** —
a Layer 3 PARA zone, an active domain that happens to contain the wiki (Q1). That ruling
makes A11-9 no longer a prose-scoping fix: the `extraction.md:81` retirement is **reversed**
(Q1b), `type: resource` returns as live vocabulary, and the build carries the batch's
`extraction.md` handshake, `version:` 5 → 6, re-acking all three consumers in the same
build. Riding the same edits (Q1e, contract half only): the `{wiki}` nested inside the
newly-PARA zone is named a **Librarian-only zone** at the surfaces a partner actually
reaches — the contract's Layer-2/Layer-3 prose, the structure table, and
`extraction.md:146`'s location-based membership clause — so the parity grant cannot be read
as partner-writability of the wiki.

All rejected alternatives in the parent filings and the rulings are settled — **do not
re-litigate**. In particular: the clerk's *explicitly closed* recommendation is overruled
on the record (Q1); the scope-the-retirement alternative (Q1b option ii) was rejected on
three recorded grounds — its lawyer's reading reproduces the exact defect A11-9 was filed
against; the `checks.md` nets half of the `{wiki}` carve-out is **build-6's scope,
atomically with the Q1c widening — do not pull it in** (roundtable A3); and A11-5's
migration clause is build-8's (Q1d).
