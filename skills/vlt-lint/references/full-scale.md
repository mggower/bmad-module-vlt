# vlt-lint — reference: full mode at scale (the fan-out workflow)

Read from Step 0 (router) only when full mode exceeds ~30 pages — scoped runs never load this.

**Full mode at scale → the fan-out workflow.** Reading the whole wiki in one context stops scaling as it grows. When full mode would cover **more than ~30 pages**, delegate the *finding* to the `vlt-lint-full` workflow (installed at `{project-root}/.claude/workflows/vlt-lint-full.js`) instead of reading every page inline:

1. **Discover the page list** — glob `{wiki}` for `*.md` (excluding `{index}`), building `pages: [{slug, path}]` with **live absolute paths** (the agents read the live tree, not a plugin cache). Build `crossLayerSlugs` by **derivation from the resolved `vault_structure` map** (the vault's `config.yaml` `vlt:` section — the *resolved* map, so vault-grown keys ride in automatically): a key **qualifies** when its resolved value names a *directory* of walker-visible linkable notes — every directory-valued key **except** the wiki's own (`wiki`), governance (`conventions`, `overlays`, `personas`), cold storage (`archive`), and report dirs (`lint_reports`, `upgrade_reports`). *(This predicate is single-homed here — other sites point at it, never restate it.)* **The same derived glob set is the SKILL's full-mode PARA page set** — the `{projects}`/`{areas}`/`{resources}` members of it, with the nested `{wiki}` subtree already carved out by the subtree-exclusion rule below. The SKILL performs the `para_*` scan over that set **itself** (step 5 below); this workflow's own page set is unchanged and stays `{wiki}`-only. The `para_*` population is walked by `scripts/lint-para-facts.py` (Step 1, both modes — its spec is `checks.md`'s population statement); the SKILL never derives P or M itself. A qualifying key's glob **excludes any subtree that is another mapped key's home** (concretely: `{wiki}` nests under `{resources}` by default — the wiki's pages are the page population, not cross-layer targets, and must not be double-covered by the parent key's glob). The qualifying set also contains two **zone roots** the map deliberately never names — `sources/` (Layer 1: real, legally linked, and by design keyless — raw-input territory is the human's to organize, and partners may not write it) and `_agent/` (the contract's ad-hoc owned-artifact grant means partners legally link files in unmapped `_agent/` dirs — e.g. `[[_agent/bases/wiki.base]]`); each zone root is walked recursively under the same subtree-exclusion rule above, so a mapped key's home inside it (`{overlays}`, `{lint_reports}`, `{upgrade_reports}` under `_agent/`) stays carved out with no new exclusion list. *(These two are the predicate's only deliberate exceptions to derivation-from-keys — named here, in the single home, because no honest key can exist for either zone.)* Glob each qualifying key's directory (and each zone root) for **every walker-visible file, any extension** — the missing-target contract is that only a target resolving to *nothing* is missing, so any real file is a valid target: `*.md` basenames normalize the same way page slugs are (extension stripped), non-`.md` basenames **keep** their extension (`wiki.base`), all lowercased — the reducer's normal form. Pass the union as `crossLayerSlugs` so a valid cross-layer link isn't reported as a missing target. Add `{index}`'s **own slug** (its basename, extension-stripped — `index` under the default map) to that union: the index is excluded from the *page* population by design, but `[[index]]` is a legal link to a file that exists. Also derive `stubSlugs` from `{index}` per `references/checks.md` Missing targets (the heading source is `{conventions}/wiki-index.md`, overlay-merged; the procedure lives there, once) and keep its `section located` / count facts for the Step-5 `stub_discovery:` line — a `[[link]]` to a registered stub is a recorded gap (the Stubs section is its record), not a missing target. Pass the list as an array — a present non-array is refused before dispatch (step 4). Also glob `{overlays}/*.overlay.md` and collect the convention names that have one (each basename with `.overlay.md` stripped; skip the overlay named for the `{contract}` file — it is the contract's overlay, not a convention's, and the page scanners' convention reads never consult it) — pass them as `overlayNames`, with `overlaysPath` as the resolved live absolute `{overlays}` path, so the fan-out's scanners judge each convention **merged with its overlay** exactly as this SKILL's own inline reads do (the contract's merged-on-read rule; without these args the workflow degrades loudly to a base-only sweep via `coverage_caps`). While globbing the page list, also compute a **content digest per page** and pass the `{slug: digest}` map as `pageHashes` — the findings cache's per-page half (step 2). The digest read uses an **unwrapped instrument and names it in the run's record**, per the operating contract's *Honest reporting* instrument rule (read it there; not restated here) — `shasum -a 256` over each page file is the expected instrument, but the rule names a property, not a tool. Then derive the two per-page **byte facts** the reduce's link graph and summary-length clauses run on — run `uv run --quiet "$SKILL/scripts/lint-page-facts.py" --pages <pages.json> --out <scratch>/page-facts.json` over the same `pages` list (keyed by the slugs you supplied) and pass its `pageLinks` and `summaryLengths` maps **as returned** — you never derive a link set or a length yourself, and the workflow refuses a run without them. The script implements `references/checks.md` Missing targets' population statement (only `[[ ]]`-delimited text; code spans and fenced blocks excluded) and `{conventions}/frontmatter.md`'s character-not-byte length; a page it lists as `unreadable` is named on the report's coverage cap by the workflow. The instrument is the script, by path — per the operating contract's *Honest reporting* instrument rule.
2. **Read the findings cache and compute this run's ruleset fingerprint (A11-11 direction 2).** If this run was asked to **re-scan named pages** (`full lint, re-scan <slug>`), first run `uv run --quiet "$SKILL/scripts/lint-cache.py" evict --vault-root {project-root} --slug <slug> [--slug …]` — it removes exactly those pages' records (exact slug match, no normalization), prints `evicted K of N`, and **exits non-zero when K is 0** (a slug that matched no record, or no sidecar at all — say so, do not proceed as if it had evicted). Then read the sidecar `_agent/lint-cache.json` by running `uv run --quiet "$SKILL/scripts/lint-cache.py" read --vault-root {project-root}` — it prints one JSON object (`status` `ok` | `missing` | `unparseable`, a `reason`, `records`, `count`, and on `ok` the informational `fingerprint`, `components`, `written`) and **exits 0 in all three cases**; pass its `records` as `cachedScans`, and render its `status`/`reason` into the report's cold branch. Then compute this run's **ruleset components** and pass them as `rulesetComponents` — one named slot: `convention_digests`, a `{name: digest}` map carrying **exactly the three conventions the page scanner reads — `frontmatter`, `wiki-supersession`, `write-verification` — the set single-homed as `SCANNER_CONVENTIONS` in `vlt-lint-full.js`**. A scanner-read convention moving invalidates every record, because it changes what a scanner returned; nothing else the SKILL passes does — the key is **facts, not verdicts** (A15-9): no version string, no pin vector, no `checks.md` digest, because none of those is an input to any page scanner, and the reduce re-runs over the cached facts every sweep. A name outside the three is ignored for the key (the workflow logs it once); a name missing from the three is named in `coverage_caps`. **Each digest is computed by these exact steps** (an executor that follows them lands on the same value every run, which is the property that failed): **instrument** `shasum -a 256` over the file bytes — the same instrument step 1 already names for `pageHashes`, under the operating contract's *Honest reporting* instrument rule (read it there; not restated here); **merge order** the base file's bytes, then a newline, then the overlay file's bytes where `{overlays}/{name}.overlay.md` exists — **base then overlay, never the reverse**, matching the merged-on-read contract; **encoding** UTF-8, bytes as they sit on disk, no normalization; **truncation** the first **16 hex characters**, lowercase. The `convention_digests` map's **order does not matter — the workflow sorts by convention name**, so do not invent an ordering here. **Composing the slot into the fingerprint is the workflow's** — together with the **extractor identity** (`scanModel`, which the workflow resolves itself and which the SKILL never restates) — single-homed at `vlt-lint-full.js` (it composes, this file supplies inputs — a composition stated in both places is what broke this cache); a slot or required name that is **absent** or **empty** is a cold sweep with each name listed in `coverage_caps` under its own word — `absent [convention_digests[write-verification]]` / `empty [convention_digests[frontmatter]]`, never the bare slot while the map is present — and a slot or name **present but of the wrong type** (`rulesetComponents` not a plain object, `convention_digests` not a plain object, a required name's digest not a string) is neither: the workflow **refuses before any agent dispatches** — step 4's failed-run posture, `reason: slot rendered with the wrong type: <slot> (got …, expected …)`; re-render the slot per this step and re-run, nothing was spent. **A missing, unparseable or schema-mismatched sidecar is a cold run, stated in the report — never an error and never a silent full sweep presented as a cached one.** Its instruments are named rather than assumed: the read script's `status`/`reason` for **missing** and **unparseable**, and the workflow's returned `cache_rejected` (against `cache_records_read`) for **schema-mismatched**. A run is **cold when the scan surface (`scanFingerprint`), the extractor (`scanModel`), or a scanner-read convention's merged bytes moved since the sidecar was written — and the `lint_cache:` cold reason names which.** A release that moves none of these leaves every record reusable. The workflow returns `cache_miss_terms` (`{page_bytes, scan_surface, ruleset}` — per stale record, the first key term that differed) for the term level, and the sidecar's stored `components` diffed by name against the workflow's returned `cache_components` gives the convention level (`ruleset moved: write-verification`) — compose the reason from those two, never from a guess.
3. **Invoke — by `scriptPath` at scale (A15-11).** The args object is `{ pages, indexPath, conventionsPath, overlaysPath, overlayNames, crossLayerSlugs, stubSlugs, today, pageHashes, pageLinks, summaryLengths, cachedScans, rulesetComponents }` — the live absolute `{index}`, `{conventions}`, and `{overlays}` paths (plus the `overlayNames` set from step 1), the two page-facts maps from step 1's script, and `today` as `'YYYY-MM-DD'` (the script has no clock; it needs it to compute `review_due`). On a ~146-page wiki that object is **~84KB plus the two page-facts maps** (146 `pages` / 146 `pageHashes` / 1,849 `crossLayerSlugs` / 6 `stubSlugs`), and passing it inline as `args` spends that much of the calling context before the first agent dispatches — and again on every resume. So at scale **do not compose it in-context**: derive it **by an executable you run** (a script with filesystem access — the steps 1–2 discovery — whose *output is a file path*, never the payload; an agent that composes 1,849 slugs in its context and then writes them to disk has already paid) — for the two page facts that executable is step 1's `scripts/lint-page-facts.py`, whose `--out` file the wrapper-writing step embeds; for the rest it is this recipe — have that script write a **thin wrapper workflow** that embeds it, and invoke the wrapper by path:

   ```js
   // <scratch>/vlt-lint-full-run.js — written by the discovery script, never by hand
   export const meta = { name: 'vlt-lint-full-run', description: 'one-shot wrapper: the full-lint args embedded so no payload transits the caller', phases: [] }
   const LINT_ARGS = { /* the ~84KB object, written here by the discovery script */ }
   return await workflow('vlt-lint-full', LINT_ARGS)
   ```

   then `Workflow({ scriptPath: '<scratch>/vlt-lint-full-run.js' })`. **Location:** a scratch directory **outside the vault** (`mktemp -d`), removed after the run completes — outside every vault enumeration by construction. **On resume**, pass `resumeFromRunId` **with the same `scriptPath`** — the payload lives in the file, so nothing is re-sent. The inline form `workflow('vlt-lint-full', { … })` stays the invocation for **small** sweeps (a wiki near the ~30-page threshold); on resume of an inline run, re-pass the full args object — the runtime delivers args fresh per run, so omitting them nulls `pages`/`crossLayerSlugs`/`overlaysPath`/`overlayNames`/`pageHashes`/`pageLinks`/`summaryLengths`/`cachedScans`/`rulesetComponents`/models. Either way the workflow fans out one agent per page (budget-guarded, chunked), reduces the link graph in JS over the SKILL-derived link sets (orphans / missing targets / near-duplicates), and runs an index pass + bounded cross-page contradiction-cluster pass. It is **read-only** — it returns the structured findings (Steps 2 shape, pre-fix), never writes. The workflow tiers its models for cost — page scanners default to a cheap model, the index/cluster passes to a mid model; pass `scanModel`/`indexModel`/`clusterModel` only to override (`scanModel` is the extractor identity in every cache key, so an override that is not a non-empty string is refused up front). *(`scripts/lint-page-facts.py` ships the two byte-facts; `pageHashes`, `crossLayerSlugs`, `stubSlugs`, `overlayNames`, the digests and the wrapper remain this recipe's — a whole-derivation executable is the recorded follow-on, gated on the `pageHashes` digest-form filing.)* **Fan-out currency (R4):** any ask added to the workflow that enforces a convention's rule adds that convention to its `convRead` and its `// depends_on:` ack in the same edit — the rule's full text lives in the workflow's ack header.
4. **Refuse a failed or vacuous sweep (the version-skew defence, B10-12).** Before applying anything: if the workflow returns `status: 'failed'` — its near-total-shortfall shape, **or** its pre-dispatch refusal of a wrong-typed input slot (`rulesetComponents`, a `convention_digests` entry, `stubSlugs`, `pageLinks` / `summaryLengths` or one of their per-page entries — the reason reads `slot rendered with the wrong type: <slot> (got …, expected …)`; both predicates return the same shape) — **or** a findings report that **adjudicated no page at all** — `files_checked` **and** `files_cached` both `0` — **stop** — do **not** apply fixes, do **not** persist a findings report, and do **not** write the Step-6 log line (so the `lint-debt` counter does **not** reset). A fixed workflow can no longer emit a findings report that adjudicated nothing — it errors first — so such a report arriving here means a **stale vault-local workflow copy**. The narrowing costs the defence nothing it was built for: a stale copy ignores the cache args entirely and returns `files_cached: 0`, so a stale-copy shortfall still refuses exactly as before; a **fully-cached** run adjudicated every listed page and is not a shortfall at all. Instead: write a **failed-run record** to `{lint_reports}/YYYY-MM-DD-HHMM-lint-failed.yaml` — or `…-lint-failed.json`, the same two legal persisted formats the report itself carries (`references/report.md`), same content and same fields either way (plain YAML by default: `status: failed`, the `reason`, `files_listed`, `files_checked`, `files_cached`, the `agent_failed` / `page_unreadable` slug lists, any `coverage_caps`, the `cost_accounting` object (written verbatim from the failed return — a failed sweep's numbers are still measurement evidence), `lint_cache: cold (<reason>, rejected R of P records read, evicted E by request)` composed from the failed return's `cache_records_read` / `cache_rejected` — on a type refusal the reason is the fourth vocabulary member, `slot rendered with the wrong type: <slot>`, which lives on this record and never on a findings report (`references/report.md`) — and a directed `next:` line — the failed-run shape rides the existing `{lint_reports}` dir-level Decay exemption, so it is not a second report class to reconcile). A third predicate, the persist gate's shape failure, writes the same record from Step 6 — its extra field and its `reason: shape — …` vocabulary are stated once at `report.md`, *Persist-gate reporting*. Then surface a **directed refusal** to the operator that names the cause and the next move, by predicate: a **near-total fan-out shortfall** (likely a stale vault-local workflow copy) → **re-run after `vlt-upgrade` lands the current workflow copy**; if the shortfall persists at full coverage, file it; a **wrong-typed slot** (the SKILL's own rendering error — no agent was dispatched, nothing was spent) → **re-render the named slot** (`rulesetComponents` per step 2, `stubSlugs` per `references/checks.md` Missing targets, `pageLinks` / `summaryLengths` by re-running step 1's `scripts/lint-page-facts.py`) **and re-run**. Only when the sweep executed at or above majority coverage does control fall through to fix-application below.
5. **Then apply Step 3 fixes and Step 4 backlog items yourself**, serially, from the returned `fix_now` / `flag_for_human` / `opportunities` — single-writer safety lives here in the SKILL, not in the parallel finders. The workflow sweeps `{wiki}` only — the PARA scan (`para_missing_attestation`, `para_status_unknown`, `para_type_unknown`, `para_author_unknown`), the governance checks, the enforcement doctrine meta-check, **and the `{research}`-zone graduation-candidacy pass (`linkage_ripe` / `revisit_due` + the widened `topic:`-is-a-list schema check, Step 2)** stay yours; fill those report slots from your own pass — one entry per walked file, never a rollup; the walk is `lint-para-facts.py`'s and Step 6 checks each entry against it. The research-candidacy pass runs **inline** here (per-note reads of `revisit_after:` + `sources:`, cross-read against every wiki page's frontmatter `sources:`, body `[[wikilinks]]`, and prose `## Sources` section), **not** fanned out — for the first cut and typical research-zone sizes that is fine; giving the workflow a `{research}` zone is the named **second-cut** work, not this build. The pass sees only notes on disk in `{research}` at run time and can say nothing about notes that never carried the key, which is what the report's `research_zone:` denominator states (Step 5). Honor any `coverage_caps` the workflow reports (budget stop, near-dup cap, cluster cap) by surfacing them in the report — **never present a capped sweep as exhaustive.**
   - **The findings cache (A11-11 direction 2).** After a sweep that was **not** refused, rewrite `_agent/lint-cache.json` from the run's own records by running `uv run --quiet "$SKILL/scripts/lint-cache.py" write --vault-root {project-root} --fingerprint <cache_fingerprint> --components <path|-> --records <path|->` — where `--records` is the workflow's returned **`cache_records`** array (a file path, or `-` to pipe it on stdin), `--fingerprint` is its returned `cache_fingerprint`, and `--components` is its returned `cache_components` object (informational, like the fingerprint — it is what lets the *next* cold run name which convention moved). A record the workflow refused on read-back (`scanner_return_rejected`) is already absent from `cache_records` — nothing to evict; the report's line carries the count, and the next sweep re-derives that page. **A finding the operator refuses as false** — a `fix_now` / `flag_for_human` entry whose page was served from the cache (a `fix_now` target that exists, a `missing_targets` target that does exist on disk — a cross-layer file the derivation missed) — **evicts its page's record** (`uv run --quiet "$SKILL/scripts/lint-cache.py" evict --vault-root {project-root} --slug <slug>`) **after this `write` and before Step 6 persists the report**: this write rewrites the sidecar whole from `cache_records`, reused records included, so an evict before it would be written straight back — a refused finding served from the cache would otherwise be re-served on every sweep (refuse → re-serve → refuse). The next sweep re-derives exactly that page. Record each refusal in the report's `false_positives_refused:` slot (`report.md`) — the finding, why the bytes contradict it, and the eviction. `cache_records` is already **one record per page adjudicated this run, fresh and reused** — the workflow composes every key, and **you never derive a key or a reusability judgment yourself**: reusability turns on the workflow-internal `scanFingerprint`, which this SKILL structurally cannot compute, so being asked to re-add "the reused records that are still valid" was an instruction that could not be followed. You write what you are handed. The script also removes a legacy `_agent/lint-cache.yaml` if one is present (it cannot express the per-page key even in principle, so it is deleted, never converted) and reports `legacy_removed`. **It is rewritten whole, never appended to**, so it never accumulates and never needs draining — and, for one page, `evict --slug` is the proportionate remedy; deleting the file whole stays safe and costs only a cold run. It stores **extracted facts, never verdicts**: no finding, no ruling, no dismissal, and no governance state (a human's ruling on a governance finding belongs in the decision log's `ref:`-keyed record, which the read-before-flag reads — a different mechanism with a different home). It is **not a lint report**, is not written to `{lint_reports}`, and no check's counter derives from it. Compose the report's `lint_cache:` line from the **workflow's returned counts only** (`files_checked` / `files_cached` / `cache_fingerprint` / `cache_records_read` / `cache_rejected` / `cache_miss_terms`) — never from what was passed in — so a vault whose workflow copy predates this feature renders an honest `cached 0`; add `evicted E by request`, E this run's evictions across both routes (the step-2 re-scan request and the refused-finding response above — `0` is rendered, never omitted); and on the cold branch name the moved term(s) by diffing the sidecar's `components` (from `read`) against the workflow's returned `cache_components`, with `cache_miss_terms` giving the term level.
   - **Cost + churn (A11-11 direction 0).** Surface the workflow's returned `cost_accounting` **verbatim** in the report, and compute `churn_since_last_full:` yourself: count pages in the `pages` list whose mtime postdates the previous persisted full-run report in `{lint_reports}` (the most recent prior full-mode report, by its dated filename — matching **both** persisted extensions, `.yaml` and `.json`, so a vault that persists `.json` reports is not invisible to its own history), rendered `<N of T pages changed since YYYY-MM-DD (instrument: <the unwrapped instrument that ran>)`; with no prior full report, render the literal `unmeasured (no prior full report)` — never an empty value that reads as "measured, zero". The mtime read uses an **unwrapped instrument and names it in the line** — per the operating contract's *Honest reporting* instrument rule (read it there; not restated here).

If the workflow isn't installed, fall back to reading inline. Small full sweeps (≤ ~30 pages) and all scoped runs stay inline — the fan-out only earns its overhead at scale.
